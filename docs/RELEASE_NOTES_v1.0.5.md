# DSH Desktop V1.0.5

Product Latest milestone / GitHub Pre-release: session continuity and source-preserving worktree handoff. Stable V0.5.4 is unchanged.

- Local per-session text drafts and document references persist across reloads. Attachment metadata is isolated by session/workspace, stale writes are rejected, and clearing a draft stays cleared. Rich image/chip serialization is not claimed. Closing the normal window flushes the last input before destruction.
- Foreground status distinguishes running, queued, steering, awaiting confirmation and turn outcomes. Queue, interrupt-and-continue, stop-current-turn and resume-retained-queue have separate actions; accepting a message is not reported as completing it. Stopping a turn retains its queue without automatically restarting it; the explicit resume action processes existing messages instead of submitting duplicates.
- Native worktree controls hand off an idle conversation, draft, document catalog and Git working/index state into an independent managed worktree, then back into the original directory. Each direction requires confirmation and a safety checkpoint. Source conversations and both directories remain available; external edits block an unsafe return and no commit is automatically merged.
- A fixed host-only Harness SDK channel creates a fully composed child Agent with a verified inherited event prefix. Network renderers and models do not get generic session control. Switching workspace preserves the Harness process and other live sessions. A one-use trusted preload intent selects the target before the upstream UI boots.
- Interrupted handoffs remain visible as recovery records and are not automatically repeated. A narrow startup scan-race retry handles only ENOENT involving `.dsh-mkdir-*`, with a stable session ID.

389 source tests pass. Real-renderer checks verify exact draft/reference reload, per-session isolation and toolbar-focus clearing. Paid-model checks verify inherited conversation history, target-directory file output, conflict-protected return, queue retention after stop, explicit FIFO resume, and interrupt-and-continue producing the correct marker files with the sent draft cleared. Handoff availability uses authoritative SDK state instead of a stale DOM Stop indicator; controls refresh without replacing focused list items. Git snapshot validation reads a private index copy, with split-index and external-lock regressions; an unreadable index fails closed instead of silently falling back to HEAD. Read-only native status refreshes disable optional index writes, while real mutations still respect locks. Earlier failed attempts are retained. Package, installation and public download gates are recorded separately as they complete. Unsigned automatic installation remains blocked.
